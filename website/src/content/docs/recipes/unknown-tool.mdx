---
title: Unknown tool
description: The model called a tool that doesn't exist, or passed arguments that don't match the tool's schema.
---

## Symptom

The model invents a tool name (`serch` for `search`), or calls a real tool with the wrong arguments. Dispatched blindly, that's a `KeyError` deep in your code — or worse, a silently wrong call.

## Minimal fix

Give the validator your tool set as `{name: schema}`; a call outside it is rejected:

```python
from beacon.integrations.openai_sdk import validated_tool_call

tools = {
    "search": {"type": "object", "properties": {"q": {"type": "string"}}, "required": ["q"]},
}
calls = validated_tool_call(response, tool_schemas=tools)
# a call to "serch" raises MalformedOutputError (code "openai.unknown_tool")
# a call to "search" with bad args raises SchemaValidationError
```

Every adapter follows this convention with a provider-prefixed code (`anthropic.unknown_tool`, `crewai.unknown_tool`, `mcp.unknown_tool`, …). Without a framework, pair [`parse_tool_call`](../../blocks/parse-tool-call/) with [`validate_schema`](../../blocks/validate-schema/).

## What it guarantees

- A call to a name **not** in your tool set raises deterministically, with a stable, provider-prefixed error code you can catch.
- A call to a known tool has its arguments validated against that tool's schema; the offending call is attached as `.raw`.
- Same decision on every machine — a hallucinated tool is never dispatched.

## What it does not do

- It does **not** correct the name or repair the arguments — it rejects the call so you can retry or fail cleanly.
- It does **not** dispatch the tool; it only validates the request at the boundary.
