# v2.0 · Pillar C — C ABI foundation — what changed

Everything below is **uncommitted on `main`** for you to review and commit.
Nothing was committed, branched, PR'd, or published. No existing crate changed
behaviour; the three gates hold.

## What it is

The FFI foundation for broader language reach (Pillar C): a stable **C ABI** over
`beacon-core`, so Go (cgo), the JVM (JNI/Panama) and any language with a C FFI
can call beacon with **byte-identical** output to the Python and wasm bindings.

## Scope delivered here

The full prompt scope — Go and JVM *bindings*, and a C conformance runner —
needs those language toolchains and a C compiler, which this Windows-GNU machine
does not have. What **is** buildable and verifiable here, and is done:

- **`crates/beacon-ffi`** — a new workspace crate exposing an `extern "C"` API
  over `beacon-core`, covering all 15 cross-language blocks (the same set as the
  conformance corpus). Returns beacon's canonical JSON text, byte-identical to
  the other bindings.
- **Error model**: each function returns a freshly allocated UTF-8 C string (freed
  with `beacon_string_free`) or `NULL`; on `NULL`, thread-local
  `beacon_last_error_code()` / `beacon_last_error_message()` give the stable
  beacon code and message. Panics are caught at the boundary (`ffi.panic`).
- **`include/beacon.h`** — a hand-written C header for the full surface.
- **`README.md`** — the ABI contract, memory model, build and a C example.
- **Rust tests** (8) exercising the ABI — marshalling, error codes, NUL/UTF-8
  handling, `free`, panic-free success path — with no C toolchain needed, since
  `extern "C"` functions are callable from Rust.

## Verified green (this machine, Windows GNU)

- `cargo test -p beacon-ffi` → **8 passed**; `cargo test -p beacon-core` → 112.
- `cargo clippy -p beacon-ffi` → clean (the crate opts out of the workspace
  `forbid(unsafe)` — an FFI boundary needs `unsafe` — but keeps clippy's
  `unwrap_used`/`panic` denials).
- `cargo build -p beacon-ffi` → links a real **`beacon_ffi.dll`**, a `staticlib`
  (`libbeacon_ffi.a`) and a Windows import library.

## Lint note

`beacon-ffi` is the one crate that does **not** set `[lints] workspace = true`
(the workspace forbids `unsafe_code`, which an FFI layer cannot honour). It sets
its own `[lints.clippy]` denials instead, and every `unsafe` block carries a
`SAFETY:` note.

## What you need to do / next

- Build release artifacts on each target platform (`.so`/`.dylib`/`.dll`) for
  distribution; the C ABI is frozen-shaped but not yet versioned for release.
- Add the native bindings (Go, JVM) and a **C conformance runner** that loads
  this library and asserts the shared golden corpus (`tests/conformance/`) — the
