# v2.0 · Pillar D — Conformance & determinism attestation — what changed

Everything below is **uncommitted on `main`** for you to review and commit.
Nothing was committed, branched, PR'd, or published. No existing block output,
error code or message changed; the three gates hold. No Rust changed.

## What it is

The moat, made provable as bindings multiply: a **single language-neutral golden
corpus** that every binding is asserted byte-identical against, plus a
reproducible **determinism report** published on the docs site.

## What changed vs. the v1.0 parity harness

The v1.0 cross-language test embedded its cases in Python and computed the
"expected" value from the Python package at run time — it proved Python == JS but
pinned nothing. This replaces it with a committed golden:

- **`tests/conformance/corpus.json`** — the golden: `{id, fn, args, expected}`
  per case, `expected` being the frozen canonical output string. 29 cases across
  15 blocks.
- **`tests/conformance_cases.py`** — one shared, language-neutral case list and a
  `fn -> Python-call` dispatch (`run_case`), reused by the generator, both
  runners and the report. `build_corpus()` / `load_corpus()`.
- **`tests/conformance/generate.py`** — regenerates the golden from the Python
  package (run deliberately, like a snapshot update).
- **`tests/test_conformance.py`** — the per-binding runners:
  - `test_python_matches_golden` (always; no Node needed) — the PyO3 wheels vs
    the golden.
  - `test_javascript_matches_golden` (Node-gated) — the wasm package vs the *same*
    golden, via `tests/js/parity_runner.mjs`.
  - `test_corpus_is_up_to_date` — the committed golden still equals what Python
    produces, and every dispatched op has a case.
  Both bindings matching one golden proves Python == JS **and** pins the exact
  bytes; a regression in either language fails.
- **`tests/conformance/report.py`** → **`determinism-report.json`** — runs the
  corpus through every available binding and records matches + environment (core
  version, Unicode version, platform, Python and Node versions).
- **`website/.../guarantees/conformance.mdx`** — the published attestation page
  (+ sidebar entry).
- Removed the superseded `tests/test_parity_js.py`.

## Latest report (this machine)

- **29 cases, 15 blocks.** Python **29/29** and JavaScript **29/29** —
  **all byte-identical**. Core `1.0.0`.

## Scope note

The corpus covers blocks that exist in `beacon-core` (and so in every binding).
Python-only surfaces built on the core — the provenance ledger (A), the streaming
engine (B), the `aio` wrappers — reproduce the same hashes/values by riding on
`hash_content` / `parse_partial`; they gain their own binding runners as those
bindings (Pillar C: Go / JVM / C-ABI) land. Adding a binding means adding one
runner that feeds it this corpus — no new expectations to author.
