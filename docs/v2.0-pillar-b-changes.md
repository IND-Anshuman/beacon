## What it is

A first-class streaming engine: feed chunks of a JSON response as they arrive and
pull each top-level item (array element, object member, or final scalar) the
moment it settles. The headline property is **chunk-boundary invariance** — the
same bytes split into chunks *any* way yield the same committed items and the
same final value.

## Design decisions taken (recommended defaults)

- A **stateful `StreamParser`** object, built on the **stateless `parse_partial`
  core** — exactly the shape the prompt recommends. No new parser: it drives
  `parse_partial` over the accumulated buffer.
- Commit rule that makes invariance sound: every element but the last is
  delimited (final); the last is withheld until the container completes or the
  stream is `close()`d. A bare scalar has no delimiter (`4` could become `42`),
  so scalars commit only at `close()`.
- JS/other-language parity deferred to the conformance pillar (D), as with the
  ledger. The algorithm is simple and specified; it rides on the cross-language
  `parse_partial`.

## API

- **`StreamParser`** — `feed(chunk) -> StreamUpdate`, `close() -> StreamUpdate`
  (flush a trailing scalar / truncated tail), and `value` / `complete` /
  `consumed` / `closed` properties.
- **`StreamUpdate(value, complete, consumed, committed)`** — `committed` is the
  tuple of top-level items that settled in that update, each emitted once, in
  order.
- **`stream_json(chunks: Iterable[str])`** — a generator yielding every committed
  item, for the "iterate results as they arrive" pattern.
- **`beacon.aio.stream_json(chunks: AsyncIterable[str])`** — the async-iterator
  version; each parse step runs on a worker thread.
- Exported top-level: `StreamParser`, `StreamUpdate`, `stream_json`.

## Chunk-boundary invariance (the guarantee)

For any JSON value and any two chunkings of its serialization:
`list(stream_json(A)) == list(stream_json(B))`, and the final `StreamParser.value`
equals `parse_partial(whole).value`. Proven by Hypothesis fuzz over arbitrary
JSON values and arbitrary splits (even, and one-character-per-chunk), plus unit
tests for arrays, objects, scalars, nesting, empties, and truncation.

## Streaming redaction (variant, now included)

`StreamRedactor` / `stream_redact` / `beacon.aio.stream_redact` redact a text
stream with the guarantee that **a secret is never emitted across a chunk
boundary**. It emits only the redaction of the buffer up to a cut placed *before*
any match that could still be growing (holding back `max_secret_len - 1` chars,
default 1024), so a secret spanning a boundary is held until it completes and is
redacted. The provable invariant: the **concatenated output equals `redact` of
the whole text**, for any chunking — which itself is the no-leak guarantee
(fuzz-tested over token streams and arbitrary splits). New public types:
`StreamRedactor`. Files: `python/beacon/streaming.py`, `__init__.py`, `aio.py`;
tests in `tests/test_streaming.py`; docs on the streaming page + the PII recipe.

## Streaming tool-call detection (variant, now included)

`StreamToolCalls` / `stream_tool_calls` / `beacon.aio.stream_tool_calls` emit each
tool call the moment it finishes parsing, across every format `parse_tool_call`
recognizes (Hermes, OpenAI/Anthropic JSON, Mistral, Llama, XML, python call
syntax). It re-reads the buffer with `parse_tool_calls` and returns the
newly-complete calls, so a call split across chunks is never emitted half-formed.
The provable invariant: the yielded calls equal `parse_tool_calls` of the whole
text, in order, for any chunking (fuzz-tested over multi-format sequences and
arbitrary splits — which also proves soundness, since a wrongly-emitted partial
would diverge from the batch result). New public types: `StreamToolCalls`.
